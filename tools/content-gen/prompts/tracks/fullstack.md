트랙: FULLSTACK (풀스택 — 프론트·백엔드·API·DB·배포를 아우르는 제품 엔지니어링)

이 트랙의 문항은 아래 실제 개념을 구체적으로 묻는다. 각 문항은 하나의 개념을 명확히 겨냥한다. 단일 계층에 매몰되지 않고 **계층 간 상호작용·트레이드오프**를 함께 묻는다.

## 핵심 개념 목록

- **API 설계**: REST 자원 모델링, HTTP 메서드·상태 코드 의미, 멱등성, 페이지네이션, 버저닝, 계약(contract) 정합, 에러 응답 표준화.
- **인증·인가**: 세션 vs 토큰(JWT), OAuth2/OIDC 흐름, 리프레시 토큰 회전, CORS, 프론트-백 간 자격 전달.
- **데이터베이스·모델링**: 정규화 vs 비정규화, 인덱스 트레이드오프, 트랜잭션 경계, 낙관적 동시성, 마이그레이션 안전성.
- **프론트-백 연동**: 클라이언트 데이터 패칭, 로딩/에러 UX, 낙관적 업데이트, 캐싱·무효화, 실시간(SSE/WebSocket) 개념.
- **성능·확장**: 캐시 계층(브라우저·CDN·서버·DB), N+1, 지연·처리량 트레이드오프, 수평 확장, 상태 비저장(stateless) 서버.
- **배포·운영**: 환경 분리, 무중단 배포, 헬스체크, 피처 플래그, 관측성.
- **테스트·품질**: 단위 vs 통합 vs E2E 피라미드, 계약 테스트, 회귀 방지.
- **트레이드오프 판단**: 일관성 vs 가용성, 단순성 vs 유연성, 빌드 vs 구매, 즉시 최적화의 함정.

## CODE_READING 지침

짧은 스니펫(API 핸들러·SQL·프론트 패칭 코드 등, 5~15줄)을 `content`에 `\n`으로 넣고, 계층 경계에서 발생하는 문제(예: 트랜잭션 밖 예외 처리, CORS 누락, 잘못된 상태 코드, 캐시 무효화 실패, race)를 읽어내게 한다.
